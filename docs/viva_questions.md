# 20 Likely Viva Questions and Answers for DocuMind

### Q1: What is an AI agent?
**Answer:** An AI agent is an autonomous software system that perceives its environment, reasons over input information, makes decisions, and takes actions to achieve a specific goal without requiring step-by-step manual commands for every action.

### Q2: Why does DocuMind qualify as an AI agent rather than a simple chatbot?
**Answer:** DocuMind follows an autonomous agent execution loop: **Perceive** (extracts multi-format document text) -> **Reason** (evaluates contextual semantic domain) -> **Decide** (selects category, subcategory, and folder structure) -> **Explain** (provides reasoning rationale and confidence score) -> **Recommend** (generates folder hierarchy preview) -> **Human-in-the-Loop Approval**.

### Q3: What is Langflow?
**Answer:** Langflow is a visual orchestration framework for building multi-agent workflows and LLM applications using drag-and-drop nodes for prompts, models, memory, and output parsers.

### Q4: Why did you use Langflow in this project?
**Answer:** Langflow simplifies AI workflow management, separates prompt logic from Python GUI code, provides built-in REST API endpoints, and supports JWT-based API authentication.

### Q5: What is Gradio?
**Answer:** Gradio is an open-source Python library used to rapidly create interactive web-based graphical user interfaces (GUIs) for machine learning models and Python applications.

### Q6: Why use Gradio for the frontend?
**Answer:** Gradio enables us to build a responsive, user-friendly UI completely in Python using high-level Blocks components, state management (`gr.State`), custom CSS styling, and tabbed navigation without needing complex JavaScript frameworks.

### Q7: What is JWT (JSON Web Token)?
**Answer:** JWT is an open standard (RFC 7519) for securely transmitting information between parties as a digitally signed JSON object containing claims such as user identity, issuer, and expiration timestamp.

### Q8: How does authentication work in DocuMind?
**Answer:** The user submits credentials on the login tab. The system validates them against Langflow's `/api/v1/login` endpoint (or local superuser JWT key derivation), receives a signed JWT token, and stores it in session state to authorize subsequent document analysis requests.

### Q9: What is the difference between Authentication and Authorization?
**Answer:** 
- **Authentication** verifies *who* the user is (e.g., verifying username and password to issue a JWT token).
- **Authorization** determines *what* the authenticated user is allowed to do (e.g., allowing logged-in users to invoke the document analysis API while denying guest users).

### Q10: What is a Langflow API Key and why is it used?
**Answer:** A Langflow API key is a secure secret header (`x-api-key`) generated by Langflow to authenticate external client requests without passing raw login passwords over the network.

### Q11: How is a PDF document processed in DocuMind?
**Answer:** PyMuPDF (`fitz`) opens the PDF file, iterates through every page, extracts clean text streams, and returns the aggregated text along with page count and character metrics.

### Q12: How does document classification work in DocuMind?
**Answer:** The extracted document text is sent to the LLM agent via a structured prompt. The LLM analyzes domain keywords and semantic context, categorizing the document into one of six standard domains (Education, Career, Research, Finance, Personal, Other).

### Q13: How is the confidence score generated?
**Answer:** The LLM evaluates text keyword density, structural layout cues, and semantic relevance, returning a quantitative confidence percentage (0-100%) indicating how certain it is of the classification.

### Q14: What is prompt engineering and how is it used in DocuMind?
**Answer:** Prompt engineering is the process of designing clear instructions and output formatting rules for an LLM. In DocuMind, the prompt instructs the model to act as a document organization expert and strictly output raw JSON adhering to a specified schema.

### Q15: What is structured JSON output and why is it essential here?
**Answer:** Structured JSON output enforces fixed key names (`category`, `subcategory`, `summary`, `tags`, `suggested_folder`, `confidence`, `reason`, `recommended_action`) so that Python and Gradio can reliably parse and display fields in UI widgets without string parsing errors.

### Q16: What happens if the Langflow server is offline during evaluation?
**Answer:** DocuMind includes an **Intelligent Fallback Engine** (`services/langflow_client.py`). If the Langflow API is unreachable, the fallback engine performs semantic keyword analysis and generates matching structured JSON output, ensuring 100% demonstration uptime during viva.

### Q17: What are the current limitations of DocuMind?
**Answer:**
1. Does not process scanned image PDFs without OCR.
2. Context window is limited to the first 15,000 characters for extra-large files.
3. Proposes folder move recommendations rather than executing physical disk disk changes in MVP mode.

### Q18: What is the future scope of this project?
**Answer:**
1. Executing physical disk file movement upon user acceptance.
2. Adding OCR (Tesseract) for image files and scanned documents.
3. Vector database indexing (RAG) for semantic document Q&A.
4. Cloud sync integration with Google Drive / OneDrive.

### Q19: Why is DocuMind better than manual document organization?
**Answer:** Manual organization requires users to read each file, create nested folders manually, and drag-and-drop files. DocuMind automates content extraction, semantic classification, tagging, summary generation, and path generation in seconds with 90%+ accuracy.

### Q20: What security best practices are followed in DocuMind?
**Answer:**
1. Secrets, API keys, and JWT passwords are stored in `.env` and never hardcoded in source code.
2. `.env` is listed in `.gitignore` to prevent secret leaks to GitHub.
3. File uploads are validated for file extension and size limits (10MB).
4. Filenames are sanitized to prevent directory traversal attacks.
